    #DL/T 645 动态库接入

    插件包 dlt645/1.0.0 使用现有 ABI v1 的 10 个 C 导出，内部由 Dlt645Protocol PIMPL 封装仓库内 DL/T 645-2007 C++ 协议栈。 PluginManager 已有 DLT645 默认映射，Windows 加载 proto_dlt645.dll， Linux 加载 libproto_dlt645.so。主程序通过函数表调用，不直接链接 MODULE。

    参考 ems_simulate/src/device/protocol/dlt645_handler.py 和 dlt645_compat.py： 支持 TCP / RTU、12 位 BCD 表地址、00–04 类读取、需量及发生时间、复合字段， 以及带密码的 04 类数值参数写入。服务端作为只读上送出口，本地 write 更新映像， 远端写入和管理命令返回错误，广播请求不改变映像。

    #配置

    {
  "role": "client",
  "transport": "tcp",
  "ip": "127.0.0.1",
  "port": 8899,
  "meter_address": "123456789012",
  "timeout_ms": 3000,
  "bcd_endian": "little",
  "allow_writes": false,
  "password": "00000000",
  "points": [
    {"code": "YC_voltage", "di": "0x02010100"},
    {"code": "YC_energy", "di": "0x00010000"},
    {"code": "YC_demand", "di": "0x01010000"}
  ]
}
    配置项约定
    role默认 client；server_readonly 或 server 为只读服务端
    transport / modetcp 或 rtu；默认 TCP，显式串口配置自动选择 RTU
    ip / port客户端默认 127.0.0.1，服务端默认 0.0.0.0；默认端口 8899，范围 1–65535
    meter_address / rtu_addr1–12 位十进制数字，左补零至 12 位；默认全零
    bcd_endian默认 little，表地址和密码低字节在前；big 兼容当前模拟器的 Python 库
    timeout_ms1–60000 毫秒，默认 3000；旧 timeout 使用整数秒 1–60，显式毫秒优先
    serial_portRTU 必填，如 COM3 或 /dev/ttyUSB0
    baud_rate / baudrate300–115200，默认 9600
    data_bits / databits5–8，默认 8
    stop_bits / stopbits1 或 2，默认 1
    parityeven/odd/none 或 E/O/N，默认偶校验
    allow_writes默认 false；客户端写参需显式 true
    password8 位十进制 BCD 文本，默认全零；对端按密码及权限级别验证
    points测点别名及服务端映像，每项含 di，可加 code/meter_address/field

    通道传入的 settings 支持对象或 JSON 对象字符串；顶层配置优先。 旧 connection=127.0.0.1:8899 或串口名也可使用。初始化仅校验配置，连接时才打开资源； 已连接时禁止重配置。初始化失败保留之前的有效配置。

    与当前 ems_simulate 对接时，设置 bcd_endian=big。 其 Python 库的 set_address / 密码转换直接使用大端 BCD；此选项仅改变地址和密码， 不改变 DI、数值或时间的报文字节序。标准设备使用默认 little。

    #测点与结果

    0x02010100                    # 默认表的 A 相电压
33620224                      # 同一 DI 的十进制表示
123456789012:0x02010100        # 指定 12 位表地址
0x04000105:0                  # 选择第 0 个复合字段
YC_voltage                    # points 中配置的别名

    DI 接收 uint32 整数或十进制 / 显式 0x 字符串；最高字节必须是 00–04。 field 从 0 开始。一个实例可以访问同一端点上的多个表地址，调用按实例串行执行。 业务编码如 YC_voltage 需在 points 中建立 DI 映射；插件返回协议物理值，系数换算由点映射层完成。

    DI 类别读取结果
    00 电能数值，保留单位
    01 需量数值及 occur_time；发生时间按设备本地日历转换为 UTC 毫秒
    02 变量数值，保留单位
    03 事件 / 04 参数保留所有 fields 的 name、format、unit、原始 value；可按字段索引读取数值

    结果保持输入顺序，包含 code/value/quality/timestamp，以及可用的 di/unit/fields/occur_time。 数值有效时 quality=0；缺失、未知 DI、字段越界或日期/成对字段不能表示为单个数值时， 返回 value=null, quality=1，并保留复合字段供调用方读取。X/N 数字格式可以转为数值， 日期、时间、成对事件保留原始字符串。无设备采样时标时，timestamp 使用本次读取时刻。 协议栈的 00–02 数值使用 float，调用方应按 DI 小数位比较结果。

    read_batch 返回有效数值点数；连接或调用错误返回 -1。 输出缓冲不足返回 EMS_PLUGIN_BUFFER_TOO_SMALL（-2）；使用相同点列表扩容重试会取回本次结果， 不重复网络读取。实例之间的连接、结果缓存、表地址和错误信息互相隔离。

    客户端 write 只支持 04 类单字段数值参数，并校验有限值、无符号范围及小数位。 日期、时间、复合字段和管理命令不通过 ABI v1 的 double 写接口表达。

    #只读上送

    {
  "role": "server_readonly",
  "transport": "tcp",
  "ip": "127.0.0.1",
  "port": 8899,
  "meter_address": "123456789012",
  "points": [
    {"code": "voltage", "di": "0x02010100", "value": 220.1},
    {"code": "energy", "di": "0x00010000", "value": 123.45},
    {"code": "demand", "di": "0x01010000", "value": 2.1234, "occur_time": 1767323040000},
    {"di": "0x04000105", "value": 1234},
    {"di": "0x03030000", "fields": ["000001,000002", "000003,000004", "000005,000006"]},
    {"di": "0x02010100", "meter_address": "000000000002", "value": 230.2}
  ]
}

    服务端只暴露 points 中初始化成功的 DI；按表地址维护独立映像。 00–02 使用 value，03–04 的复合值使用按定义顺序排列的 fields 字符串。 成对事件用 first,second，其他字段使用去掉小数点的定宽十进制数字。 本地 write("voltage", 230.2) 更新已有映像；不添加未配置 DI，不支持局部复合写。 需量本地数值更新同时更新发生时间。停止监听后等待通信线程退出，随后才释放库租约。

    #构建与验证

    需要 C++17、CMake、Boost 1.83+ 头文件。以下仅构建 DLT645，不依赖 hiredis/libmodbus。

    # MSVC：在开发者终端执行；MinGW 可改用 -G "MinGW Makefiles"。
cmake -S backend/src/net/protocol -B build/dlt645 -G "Ninja Multi-Config" -DEMS_BUILD_MODBUS=OFF -DEMS_BUILD_IEC104=OFF -DBOOST_ROOT=C:/deps/boost
cmake --build build/dlt645 --config Release
ctest --test-dir build/dlt645 -C Release --output-on-failure
cmake --install build/dlt645 --config Release --prefix build/dlt645-install

    Linux 使用同一源码入口和可用的生成器，单配置生成器加 -DCMAKE_BUILD_TYPE=Release。 Windows 多配置产物位于 lib/<配置>/proto_dlt645.dll；Linux 位于 lib/libproto_dlt645.so。 安装包位于 plugins/dlt645/1.0.0/，包含动态库和 manifest.json；协议栈静态编入插件， 无需独立 DLT645 或 Boost DLL。编译器运行库仍应与部署环境匹配。

    安装包加载可设置插件根目录并注册相对路径：

    manager.set_plugin_dir("<安装目录>/plugins");
manager.register_mapping("DLT645", "dlt645/1.0.0/proto_dlt645.dll");
auto* instance = manager.load("DLT645");

    新增 10 项集成测试覆盖动态加载、配置、00–04、多个表、写参、只读出口、缓冲重试、 重连、串口打开失败和并发实例。可使用模拟器虚拟环境执行双向 TCP 互通检查：

    <ems_simulate>/.venv/Scripts/python.exe backend/tests/net/protocol/dlt645_simulate_interop.py --simulate-root <ems_simulate> --plugin build/dlt645/lib/Release/proto_dlt645.dll

    该脚本直接使用模拟器的兼容封装和已安装 Python 库，只监听回环地址，日志写入本仓库 .cache/。 MinGW DLL 若未随插件部署，可传 --runtime-dir <MinGW>/bin 提供编译器运行库目录。 Windows MSVC / MinGW 已验证；Linux/macOS 尚未执行平台构建，真实 RTU 收发仍需串口或现场设备验收。
