    #IEC 61850 动态库接入

    本文定义 IEC 61850 接入现有协议动态库体系的实现契约，以仓库内 backend/third_party/libiec61850 为 C 协议栈，参考 ems_simulate 的模型、DataSet、报告和控制实现。 当前状态：MMS 轮询/报告客户端、持久 DataSet 批读、固定模型只读服务端与 RTDB 自动上送已实现。 客户端支持 read_mode=poll/report/hybrid；服务端支持本地更新、远端读取和 URCB/BRCB。 客户端写入/控制仍拒绝。Web 配置 API 的协议白名单与界面接入尚未扩展： 采集与上送入口使用已有数据库配置；启用 can_forward 的 MMS 服务端由采集进程独立线程维护。

    #1. 现状与接入范围

    项目仓库现状 / 本文约定
    依赖已有 backend/third_party/libiec61850/；其 CMake 声明库版本为 1.6.2，最终以入库源码为准
    加载器PluginManager::default_lib_map() 已预留 IEC61850 → proto_iec61850.dll / libproto_iec61850.so
    插件已有 PIMPL 协议对象、ABI v1 桥、manifest、独立 CMake 目标和真实 C 栈回环测试
    Handler复用通用 PluginHandler，通过工厂按 IEC61850 名称创建，无需专用处理器
    采集入口CfgLoader 已支持 MMS 名称与 YC/YX 路由，按物理引用生成初始化点目录；YK/YT 当前拒绝
    ABI保留 ABI v1 的 10 个必需导出；新增可选 ems_plugin_update_image，旧插件仍可加载
    已实现MMS client：模型校验、标量/DataSet 读取、URCB/BRCB、缓存与周期完整性轮询；server：固定模型、读取、报告和本地映像更新
    后续验收批次客户端受控写入、现场 IED 互通与 Web 配置入口
    独立扩展GOOSE、Files、Logs、Setting Groups、TLS/ACSE 认证不计入首批

    接入范围不包含 SV 和图形化建模，也不将其列为后续扩展或验收项。 SCL 仅用于 ICD/CID/SCD 文件导入、校验与协议模型解析。

    协议语义使用 iec61850_mms，现有运行时插件名保留 IEC61850。 配置编译器须显式将 iec61850_mms 和旧名 iec61850 映射到现有运行时类型， 保留已有枚举编号；旧名仅表示 MMS。iec61850_goose 不映射到此插件。 协议插件支持 acquisition + client + connect 和 forwarding + server + listen。 CfgLoader/ems-collector 仍仅接受 MMS client，不能把采集线程当作上送进程； 服务端由独立 Handler 调用方更新本地映像，详见通道协议契约。

    #2. 动态库与资源边界

    一个采集通道对应一个 MMS association 和一个插件实例。相同 IP/端口的独立通道不自动 共享会话；同通道绑定可映射同一 IED 的多个 LD。LD 是协议模型节点，不要求为每个 LD 新增通信设备。站、单元、设备、部件仍统一使用 cfg_device，部件通过 source_device_id 指向通信设备，点归属与采集路由分别维护。

    首批实现文件：

    backend/include/net/protocol/iec61850_protocol.h      # C++17 PIMPL 接口
backend/src/net/protocol/iec61850/
  CMakeLists.txt                                   # MODULE 与打包
  iec61850_protocol.cpp                             # 会话、模型、缓存、读写
  iec61850_plugin.cpp                               # ABI v1 桥与异常转换
  iec61850_plugin.def                               # Windows 导出列表
  mms_server_runtime.h / mms_server.cpp              # 固定模型只读服务端
backend/tests/net/protocol/iec61850_runtime_test.cpp

    协议对象仅在 DLL/SO 内创建、调用和销毁。第三方头文件、IedConnection、 MmsValue、控制对象、锁和线程只存在于 Impl，不暴露给主程序。 主程序链接 ems_protocol_runtime / net_handler，不链接 proto_iec61850 或第三方栈。C 边界不传 STL、异常、虚表或第三方指针。

    导出符号IEC 61850 实现要求
    ems_plugin_info静态元信息，api_version=EMS_PLUGIN_API_VERSION、protocol_name=IEC61850
    ems_plugin_create / ems_plugin_destroy库内分配与释放；失败不泄漏，异常不跨 ABI
    ems_plugin_init解析配置，校验点、引用、角色和资源上限；不连接 IED、不遍历远端模型
    ems_plugin_connect建立 MMS association，校验模型；启用报告时完成订阅准备，失败清理部分资源
    ems_plugin_disconnect停止任务和回调、释放会话；重复调用成功；不能安全停止时返回失败并保留库租约
    ems_plugin_is_connected1 表示 association 可用，0 表示未连接；不代表所有点都有有效初值
    ems_plugin_read_batch按请求顺序返回 JSON；返回 quality=0 的点数，部分点失败不丢弃成功点
    ems_plugin_write客户端拒绝；服务端仅更新已配置值点或 quality_code，不发送远端控制
    ems_plugin_last_error返回实例持有的诊断文本，调用方在下次操作前复制

    所有公开操作按实例串行。回调只复制必要数据并投递队列或唤醒等待者，不发起同步 MMS 请求、不访问数据库、不重入 Handler、不执行停止/卸载。队列锁与请求锁分离；等待 CommandTermination 时不能持有回调需要的锁。禁止在库静态初始化或 DllMain 中建连、 起线程或执行网络清理。

    #3. 点地址、模型与四遥映射

    #3.1 引用规范

    值点使用完整对象引用和独立 FC；不能套用 Modbus 寄存器或 IEC104 IOA 编码。

    类别示例说明
    数据叶子SIMLD0/MMXU1.TotW.mag.f + MXLD/LN.DO.DA，可有多级 DO/BDA
    状态叶子SIMLD0/XCBR1.Pos.stVal + STstVal 的类型由模型决定
    控制对象SIMLD0/CSWI1.Pos + CO指向 DO，由 ControlObjectClient 执行控制服务
    DataSetSIMLD0/LLN0$dsMeasurements插件内部统一为 libIEC61850 DataSet 引用形式
    BRCB / URCBSIMLD0/LLN0.BR.brcbMeasurements01 / SIMLD0/LLN0.RP.urcbMeasurements01显式区分 BR/RP 与实际实例名

    SIMLD0 是示例中的线上 LD 名称，不能盲目用 IED 名称加 ldInst 拼接； 应以 SCL 的有效 LD 名或远端目录结果为准。点值引用不插入 .MX. / .ST.， 底层 MMS $ 变量名只在适配层转换；报告 DataReference 中的 FC 段应单独解析。 DataSet 的 LD/LN.dsName 可在输入边界规范化为 LD/LN$dsName，不能对所有引用做 同一种字符串替换。RCB 必须包含 BR/RP；不根据名称前缀猜测控制块类型。

    插件 point_code 使用配置中唯一的 points[].code。配置编译器可生成 <FC>:<完整对象引用> 作为内部读路由编码，例如 MX:SIMLD0/MMXU1.TotW.mag.f， 但该编码仍必须出现在初始化点目录中，不能作为绕过白名单的任意读写入口。 写路由用稳定点 ID 派生的独立别名，避免值叶子与控制 DO 混淆。缓存键为 (实例, object_ref, fc)，不能仅按业务短名、DO 名或 RptId 建索引。

    #3.2 模型校验与值类型

    连接时只校验配置用到的对象、FC、MMS 类型及 DataSet/RCB，不要求每次启动全量发现 所有 LD/LN/DO/DA。完整模型浏览作为独立管理任务，设总截止时间、节点数和深度限制， 按需读取描述，不逐叶反复探测全部类型。SCL 可提供离线元数据，但不代替线上校验。 .stVal / .ctlVal 的类型和 FC 必须来自模型及配置，不能只按名称推断。

    EMS 点类协议含义映射要求
    YcPoint / cfg_point_ycMX 下的数值叶子如 mag.f / mag.i，比例与偏移由上层统一换算
    YxPoint / cfg_point_yxST 下的布尔、枚举或状态值保留原始状态；DPC 位置中间态/坏态按配置标为无效
    YkPoint / cfg_point_ykCO 控制对象通过控制模型选择/执行，不直接写状态值
    YtPoint / cfg_point_ytSP 数值设定，或 CO 模拟量控制对象必须声明 write_mode=attribute/control，不能把两者混用

    四遥继续使用四张表和四类对象，共享 PointBase。YK/YT 在实时侧都属于 Command， 靠运行记录的 point_type 区分，不新增配置单表或配置 point_type 列。

    ABI v1 的输入写值和通用 PointValue 都以 double 为数值载体。首批读取支持 BOOLEAN、 有符号/无符号整数、有限 FLOAT/DOUBLE、模型声明的枚举；布尔返回数值 0/1。 整数仅在模型范围内且绝对值不超过 2^53-1 时进入公共数值；大整数保留十进制原文 作为诊断并返回无效值，不能静默截断。字符串、时间、品质位串、结构和数组不强制转 double；结构/数组中的标量需按已校验的模型路径投影。诊断可保留原始 MMS 类型和值， 大小必须有界。APC 的 ctlVal 可能是 AnalogueValue 结构，须按实际类型构造；未实现 该结构时明确拒绝，不能直接传一个 float 冒充已支持。

    数组标量引用使用零起始的 (index)，如 SIMLD0/MMXU1.Samples.values(1)； 首批支持每条引用一个数组索引，不支持嵌套数组索引。点 code 最长 256 字节， 线上 LD 与含 FC 的 MMS item 名各不超过底层接口允许的 64 字节。

    #4. 插件配置与数据库接入

    以下为已支持的轮询客户端配置，用于 Handler/插件初始化，不是 Web API 请求体。 示例引用必须替换为被测模型中实际存在的对象。纯轮询模式可作为第一批实现的配置：

    "reports": [],
    "points": [
      {
        "code": "active_power",
        "object_ref": "SIMLD0/MMXU1.TotW.mag.f",
        "fc": "MX",

        "timestamp_ref": "SIMLD0/MMXU1.TotW.t"
      },

    配置默认 / 校验要求
    protocol / local_role / transportIEC61850 / client 或 server / tcp；role=server_readonly 同样表示只读服务端
    connection必填 host:port；MMS 默认端口为 102，联调用 10102 需两端一致；不提供端点时不得悄悄连接本机
    timeout_ms默认 3000，1～60000 ms；单次 MMS 服务预算
    connect_timeout_ms默认 3000，1～60000 ms；与请求超时分别设置
    discovery_timeout_ms默认 60000，1～600000 ms；整次模型校验/发现总预算，不是每个节点的超时
    read_modepoll；report 初读后只读报告缓存，hybrid 另按顶层 poll_interval_ms（默认 1000）执行完整性轮询
    stale_ms默认 30000，0 关闭超期检查，最大 86400000 ms；使用单调接收时间
    allow_writesfalse；开启仍须逐点声明写模式，并通过绑定控制权限校验
    max_points / max_model_nodes / max_model_depth默认 65536 / 100000 / 32；正整数，上限分别为 65536 / 1000000 / 64
    report_queue_size默认 1024，16～65536；队列同时受 8 MiB 估算字节上限约束；满时标记无效并重同步
    pointscode 非空且唯一；对象引用/FC/类型合法，同一物理点可有多个业务别名，网络读取合并
    datasets / reports显式列表；不自动创建/删除远端 DataSet，不占用所有发现的 RCB

    通用 Handler 已支持顶层参数优先于 settings，settings 可为对象或 JSON 对象字符串。 iec61850 必须作为完整对象提供；顶层存在时整体优先，不对两份嵌套配置做隐式深合并。 插件校验 iec61850 内的未知字段；未实现的认证、TLS、GOOSE 等配置应报不支持， 不能忽略后按无认证/其他协议运行。ISO selector、AP-title、AE qualifier 等需要扩展时 再定义显式配置，首批使用栈默认参数并记录兼容性限制。

    #4.1 数据库存储与运行目录

    接入使用现有行结构，不新增表、不引入配置版本：

    位置存储 / 编译规则
    cfg_channelprotocol=iec61850_mms、conn_mode=tcp_client、endpoint、周期和请求超时；角色来自连接模式
    cfg_channel.serial_json现有通用 JSON 承载字段中放 iec61850 对象及通道级 DataSet/RCB 参数；虽名为 serial_json，当前编译器会把它作为通用 settings 来源
    cfg_binding关联通信设备与通道；can_collect/can_control/can_forward 限制路由；device_address 不解释为从站整数，也不替代完整对象引用
    四遥表 protocol_address_json保存 object_ref/fc/quality_ref/timestamp_ref 等点参数，控制点增加 write_mode 和控制属性；类型结合既有 wire_type 校验
    CfgLoader增加 MMS 名称映射和地址编译，聚合绑定的四遥路由生成初始化 points，不能直接把数据库业务 code 当成唯一物理地址
    配置热加载保存即生效，站根 cfg_device.config_revision 单调递增，消费者轮询后重建受影响运行目录与会话

    CfgLoader 已接受该协议并检查通道角色、点类型、重复物理引用的配置冲突和绑定权限。 通道 serial_json.iec61850 不得手工配置 points，该目录从 YC/YX 表生成； 相同物理引用的业务点可复用一致的协议定义。wire_type 通过 bool、i8/i16/i32/i64、 u8/u16/u32/u64、f32/f64 映射到 MMS 类型类别，实际位宽与有效范围由线上模型校验。 对象路径、DataSet 或模型发生变化时先停旧回调/会话，再替换目录，不在接收回调中改模型。 SCL 文件导入直接更新既有配置，由配置导入层完成校验与协议模型解析。

    #5. MMS 读取与 DataSet 批量读取

    1. 创建 IedConnection，分别设置连接和请求超时，建立 association。
    2. 用模型服务校验配置对象的 FC、MMS 类型与结构，缓存模型规格；失败给出具体引用。
    3. 对配置的持久 DataSet 读取有序目录，建立成员索引、FC 与模型叶子的映射。
    4. 每批只读覆盖请求的 DataSet；未覆盖的点使用 IedConnection_readObject 读取。
    5. 投影标量并组合品质/时标，再按原请求顺序输出，包括重复请求和失败条目。

    DataSet 使用 IedConnection_readDataSetValues 等 C API；必要的厂商兼容通过 底层 NamedVariableList 访问封装，不能依赖 Python/SWIG 包装函数。一个 DataSet 可以 包含不同 FC；按其实际成员目录读取，不能因按 FC 分组而修改成员顺序或假定整个 DataSet 只有一种 FC。相同 DataSet 每批最多读取一次，多个业务点复用结果。 当前每次 DataSet 读值后会再次读取目录，确认成员与建连时一致后才提交映射结果； 因此每个使用的 DataSet 通常有一次读值和一次目录请求。发现目录变化时关联点失效， 需断开后重新连接以重建投影。模型结构在 association 内保持固定，远端模型变更后应重连。

    FCDA 可能是整个 FCD/结构、数组或标量。必须按目录序号和模型规格投影：结构中的 mag.f/q/t 不可按“第一个数值”猜测；成员数量或运行类型不匹配时该成员失败。 DataSet 目录变化时废弃旧投影，重新校验后才恢复使用。部分成员 DataAccessError 只影响对应点，整次服务失败影响该 DataSet 覆盖的点；单点回退只读未覆盖的点， 不对失败 DataSet 的全部成员无界重试。

    每次批读有总预算，剩余时间不足时停止新增请求，剩余点输出超时无效。 单次请求预算取 min(timeout_ms, 批次剩余时间)；初期批次总预算使用 timeout_ms，大点表由上层拆批。不得把每点完整超时相加后长期阻塞调度。 DNS 解析、系统线程退出不承诺硬截止时间；停止需等底层调用安全结束。 一次 DataSet 响应只保证该响应的成员关联，不宣称跨 DataSet、跨点或全站同时采样。

    #5.1 返回值、品质与时间

    [
  {
    "code": "active_power",
    "value": 125.5,
    "quality": 0,
    "timestamp": 1793577600123,
    "object_ref": "SIMLD0/MMXU1.TotW.mag.f",
    "fc": "MX",
    "mms_type": "float32",
    "iec_quality": 0,
    "timestamp_source": "device",
    "source": "dataset"
  },
  {
    "code": "breaker_position",
    "value": null,
    "quality": 1,
    "timestamp": 1793577600123,
    "error": "not_initialized"
  }
]

    quality=0 仅表示满足本地有效性策略；缺值、断线、过期、类型不符、非有限值、 坏状态或读取错误返回 value=null/quality=1。保留 IEC 原始 q 和服务错误。 q 的 validity 非 good，以及 overflow、outOfRange、badReference、oscillatory、failure、 oldData、inconsistent、inaccurate、test、operatorBlocked、替代源等按首期保守策略 判为无效，不能拿 IEC q 位串直接替代公共 quality 整数。

    配置 quality_ref/timestamp_ref 时，其读取失败会使该样本无效；未配置时记录 quality_source=unavailable，仅依据读取结果判断，不伪造设备 q=good。示例的 iec_quality=0 仅用于确实读到了 q 的场景。优先在同一 FCD/DataSet 中取得值、q、t； 分开读取时标记 metadata_coherent=false，不宣称来自同次设备采样。

    时间统一为 UTC Unix 毫秒。配置并成功读取的设备 t 优先；检查时间品质并保留原始 时间品质，时钟失败/未同步按保守策略使样本无效。没有设备时标时使用接收时刻， timestamp_source=received。报告 TimeOfEntry 仅作报告诊断，不冒充各成员采样时刻。 过期判断使用单调接收时间，不能用可能跳变的系统时钟或设备时标。report 模式需配置 完整性报告或周期刷新：相同值的重新读取/报告也更新接收时间，避免静态点永久过期。

    结果 JSON 由插件序列化到调用方缓冲区并以 NUL 结尾。缓冲不足返回 -2，缓存本次 序列化结果；同一有序编码列表扩容重取不重复网络读取、不混入新报告。新请求、写入、 重初始化或断开连接使待取结果失效。通用 Handler 当前从 64 KiB 扩容至 8 MiB， 每批上限 65536 点；实现需在分配前检查结果尺寸和资源上限，错误可诊断。 额外字段进入 PointValue.details，不据此声称已写入 RTDB 或形成可靠事件历史。

    #6. Reports 报告采集

    在第 4 节客户端配置中设置 read_mode=report 或 hybrid，并添加：

    {
  "reports": [
    {
      "rcb_ref": "SIMLD0/LLN0.BR.brcbMeasurements01",
      "dataset_ref": "SIMLD0/LLN0$dsMeasurements",
      "required": true,
      "gi_on_connect": true,
      "integrity_period_ms": 10000,
      "trigger_options": ["dchg", "qchg", "dupd", "integrity", "gi"]
    }
  ]
}

    该片段是 iec61850 内的增量字段，不是完整初始化配置。 required 默认 true，gi_on_connect 默认 true，integrity_period_ms 默认 10000， 范围 1000～86400000 ms；请求触发项须获 IED 支持，否则报告配置失败。 poll 模式必须使用空 reports；report/hybrid 至少配置一个报告。订阅总数最多 128。 report 模式要求所有值点及其 q/t 均被成功启用的报告覆盖；未覆盖点应改用 hybrid。 报告引用的 DataSet 会自动加入校验目录，无需重复放入 datasets。

    启用前读取 RCB 的 DataSet、ConfRev、RptEna、所有权/保留状态和能力。仅申请配置的 可用实例，不抢占其他客户端；不默认改写 DatSet/RptId，不执行 PurgeBuf。 先安装回调再启用报告/GI；required 报告失败则连接阶段清理并报错。 required=false 仅允许 hybrid 模式明确降为轮询并输出告警；report 模式不得假成功。 可选 RCB 或其专用 DataSet 不存在时，hybrid 返回有效轮询结果并附 report_warning； 显式 datasets 列表和 required 报告的 DataSet 仍必须校验通过。警告文本限制为 2 KiB。 订阅不改写远端 RptId/DatSet，并核验 TrgOps/OptFlds/IntgPd 回读。URCB 使用 Resv， 支持 ResvTms 的 BRCB 使用 1 秒保留；正常停止主动禁用并释放本实例拥有的控制块。

    底层 C 栈按 RptId 匹配接收 handler，因此同一 association 的重复 RptId 明确拒绝， 不假装能按 RCB 区分相同 wire ID。不同 association 可使用同一 RptId，缓存和队列完全隔离。

    接收规则：

    • 以 association 与规范化 RCB 引用隔离订阅，RptId 只是诊断属性；同 RptId、多客户端、 同名 RCB 不得串数据。可选字段必须先检查是否存在，再调用相应 getter。
    • 按 inclusion 与原 DataSet 索引更新包含的成员；若 libIEC61850 已提供全长成员数组， 仍只采纳本报告包含的项。未包含项保留旧样本，不能置零或误移到前一个索引。
    • 初读期间也可能到达报告；每次初读开始前记录各点接收状态，提交时不覆盖期间已到达 的较新报告。GI 只更新包含成员，不能仅凭 GI 请求成功把全部点标为已初始化。
    • qchg 即使值未变也更新品质；dupd / integrity / GI 更新接收时间；保留 reason、 SqNum、ConfRev、EntryID、BufOvfl 与接收时间。ConfRev 是 IEC 报告协议属性， 与 EMS 的 cfg_device.config_revision 独立，不形成数据库配置版本。
    • 分段报告按连接/RCB、SqNum、SubSqNum 和结束标记有界组装，设请求超时作为组装预算； 缺段、越界、目录不符时废弃未完成组并重同步，不能误当完整 DataSet。
    • BufOvfl、序号缺口、队列满或 ConfRev 变化均表示数据可能不完整；标记关联点无效， 重读目录或完整数据并诊断。不能只留旧 good 值。无变化的普通报告静默期不等于断线。

    回调只复制本报告包含成员的已校验标量；实例工作线程在请求锁内处理事件、刷新缓存和 执行 hybrid 轮询，回调不等待该锁。分段组装的总估算字节也限制为 8 MiB，重复成员、 乱序、缺段和组装超时均触发重同步。URCB 序号按 8 位、BRCB 按 16 位处理回绕。 初读/重读后再合并期间到达的报告，避免初读覆盖报告；ConfRev 或目录不符使会话关闭， 由重连重建模型。结果 report 中保留 reason、sequence、conf_rev、EntryID、TimeOfEntry、 resync_count 与 last_resync_reason，重同步完成的样本保留 recovered 标识。

    BRCB 初次启用或溢出后，历史补送不能覆盖当前值初读。此时等待覆盖全部 DataSet 成员 的 GI/完整性报告后再提交缓冲报告；BRCB 必须启用连接 GI 或完整性触发。 重同步会再次请求已配置的 GI；纯 report 模式的正常静默期不发起周期网络读取。

    断线后清空当前值的有效状态；重连重新校验模型并申请报告，旧连接的迟到回调不能更新 新缓存。BRCB 只有在 IED 保留缓冲且恢复条件满足时才可能补送；首期不持久化 EntryID， 不承诺跨进程恢复或 SOE 不丢失。URCB 不具备断线历史恢复能力。 最新值缓存可服务周期采集，可靠事件流须另按公共事件接口设计。

    #7. 遥控、遥调与写入结果

    写入功能须单独验收。除 allow_writes=true，还要有绑定 can_control、有效命令路由、 明确的写模式、范围和实际模型类型。以下为 points 中的控制点例子：

    {
  "code": "breaker_command",
  "object_ref": "SIMLD0/CSWI1.Pos",
  "fc": "CO",
  "write_mode": "control",
  "control": {
    "timeout_ms": 3000,
    "origin_category": 2,
    "origin_identifier": "EMS",
    "test": false,
    "interlock_check": true,
    "synchro_check": true
  }
}

    以下仍为客户端控制的待实现契约。write_mode=attribute 计划仅开放显式配置的 SP 数值叶子，通过类型化 MMS Write； CF/SG/SE 等配置与定值组服务不由通用数值 write 隐式开放。write_mode=control 通过 ControlObjectClient 执行，不直接写 .stVal 或 .Oper.ctlVal。 control.timeout_ms 默认采用通道请求超时，范围 1～60000 ms；origin 必填并与 IED 允许的类别匹配；检查位由工程配置明确给出，不通过失败后降低检查来重试。

    实际 ctlModel流程
    0 status-only拒绝，不发送命令
    1 direct / normalOperate，检查返回值及 LastError
    2 SBO / normalSelect 成功后 Operate
    3 direct / enhancedOperate 后等待对应 CommandTermination，并检查 LastApplError/addCause
    4 SBO / enhancedSelectWithValue 后 Operate，再等待对应 CommandTermination

    实际 ctlModel 和 ctlVal 类型以在线模型为准，不用离线 ICD 强制覆盖。 同一 association 内复用每个控制对象，以保持库管理的 ctlNum；重连后重建。 DPC 的状态是枚举，但其控制值可为 BOOLEAN，不能照搬 IEC104 的 1/2 双命令编码。 布尔只接受 0/1，整数不接受小数或越界，浮点须有限并检查转换范围。 控制对象按引用关联在途命令，同一对象只允许一个序列；选择、执行和终止等待共用总预算。 首期不支持时间激活控制，Operate 的执行时间设为 0。

    MMS 请求成功、正常安全模型的协议确认、增强模型的终止成功和设备物理到位是不同阶段。 ABI v1 只能返回 0/-1：0 表示完成该模型要求的协议确认；物理到位由状态回读另行核验。 失败诊断应区分 rejected、not_sent、result_unknown，保留 IedClientError 与 LastApplError/addCause；这些状态目前不属于统一 ABI 的结构化返回值。

    命令发出后遇到超时/断线可能已经执行，结果按未知处理；普通属性写入同样不自动重发。 关闭该 association 并使旧在途控制失效，避免迟到终止完成新命令；由上层读取状态并决定 下一步。retry_times 只用于连接/幂等读取，不适用于控制执行。 选择成功但尚未执行时可尝试取消，取消失败仍需保留诊断。 模拟器的自动重连后重写逻辑只作参考，本插件不照搬到生产命令链路。 命令仲裁、持久化和可靠结果事件仍遵守采集/公共命令设计，插件不自行扩大控制权限。

    控制状态机参考官方控制指南， 终止回调和错误查询遵循官方控制 API。

    #8. MMS 只读上送与 SCL 边界

    local_role=server（或 role=server_readonly）已支持固定模型监听。 模型由显式 points、datasets、reports 生成，不在连接中改变结构；不直接读取 SCL XML， 也不把 ICD/CID/SCD 交给 ConfigFileParser。SCL 解析属于配置导入层的后续能力， 需要选择具体 IED/AccessPoint 并输出本节支持的点与模型定义。

    {
  "protocol": "IEC61850",
  "local_role": "server",
  "connection": "127.0.0.1:10102",
  "iec61850": {
    "ied_name": "EMS",
    "max_connections": 8,
    "report_buffer_bytes": 65536,
    "points": [
      {
        "code": "power",
        "object_ref": "SIMLD0/MMXU1.TotW.mag.f",
        "fc": "MX",
        "mms_type": "float32",
        "quality_ref": "SIMLD0/MMXU1.TotW.q",
        "timestamp_ref": "SIMLD0/MMXU1.TotW.t",
        "quality_code": "power_quality",
        "value": 125.5
      },
      {
        "code": "status",
        "object_ref": "SIMLD0/MMXU1.Status.stVal",
        "fc": "ST",
        "mms_type": "boolean",
        "value": true
      }
    ],
    "datasets": [
      {
        "dataset_ref": "SIMLD0/LLN0$measurements",
        "members": [
          {"object_ref": "SIMLD0/MMXU1.Status.stVal", "fc": "ST"},
          {"object_ref": "SIMLD0/MMXU1.TotW", "fc": "MX"}
        ]
      }
    ],
    "reports": [
      {"rcb_ref": "SIMLD0/LLN0.RP.urcb01", "dataset_ref": "SIMLD0/LLN0$measurements"},
      {"rcb_ref": "SIMLD0/LLN0.BR.brcb01", "dataset_ref": "SIMLD0/LLN0$measurements"}
    ]
  }
}

    服务端每个值点须显式指定 mms_type；boolean、integer、unsigned、float32、float64 分别生成布尔、INT32、UINT32、FLOAT32、FLOAT64。支持标量和复合 DA 路径，暂不生成 数组或由 SCL 描述的任意复杂 CDC。LD 使用显式功能命名，不按 ied_name 猜测前缀。 缺少 value 时必须配置 quality_ref，初值为 0 且质量无效。iec_quality 为 0～8191； timestamp 可指定精确 UTC 毫秒，未指定使用当前时间。不同值点不能共享 q/t 属性， 同一物理点的别名需使用一致定义。quality_code 必须唯一且不能与值点 code 冲突。

    服务端 datasets 是带 members 的对象数组，客户端 datasets 是引用字符串数组。 RCB 与对应 DataSet 须位于同一 LD/LN。每客户端分配独立 RCB 实例，例如 urcb01/urcb02， 不共享一个已占用实例；RptId 默认使用完整 RCB 引用，在服务器内必须唯一。 可配置 rpt_id、conf_rev、buffer_time_ms、integrity_period_ms、trigger_options： 默认分别为 RCB 引用、1、0 ms、10000 ms 和五种常见触发。conf_rev 是报告协议属性， 不增加 EMS 配置版本。max_connections 为 1～100；每 RCB 缓冲默认 64 KiB，范围 4 KiB～8 MiB，所有 RCB 的配置缓冲合计不超过 64 MiB。

    Handler/ABI 的本地 write(power, value) 在同一模型锁内更新值、good q（invalid_values 命中时为 invalid）和当前 t；write(power_quality, mask) 只改变 q/t，用于标记输入失效， 不会覆盖保存的数值。该别名也可通过本地 read_batch 查询。未知点、NaN、越界或错误 类型均拒绝；服务端 disconnect/connect 保留映像，成功重新 initialize 才替换模型。

    只发布配置白名单的监视对象、DataSet 和 RCB；本地 write 更新映像，远端数据写入、 控制、定值切换及模型修改均拒绝。报告所需的 RCB 保留、使能与 GI 是协议服务操作， 可在各客户端权限及所有权规则内开放，不能因“只读”一律禁止而使报告不可用。 更新使用服务器模型锁及类型化 update API，值、q、t 在同一临界区提交。 输入失效必须体现在 q，不能持续对外呈现 good 的旧值。 未配置 q 的点必须提供初值，调用方无法通过此类点表达来源失效，应为需要质量传播的 上送点配置 quality_ref/quality_code。RTDB 自动上送使用下面的批量映像接口，保留来源时标。 每客户端报告状态隔离；模型结构变更先停止服务器及全部回调，再重建模型。 不在本方案中引入模型草稿/发布/回滚或文件代际编号。

    #8.1 采集进程自动从 RTDB 上送

    ems-collector 将启用的 IEC61850 tcp_server 通道交给独立 ForwardingChannel， 不会执行采集读取或把出口数据回写 RTDB。该通道至少有一个启用设备绑定，且绑定须 设置 can_forward=1、can_collect=0、can_control=0；父设备和通道也须启用。 源点仍保留自己的采集 binding，不创建新的四遥点副本，也不增加配置表。

    在 cfg_channel.serial_json 中设置固定服务端模型与 forwarding 数组，例如：

    {
  "iec61850": {
    "ied_name": "EMS",
    "points": [
      {
        "code": "power",
        "object_ref": "EMSLD0/MMXU1.TotW.mag.f",
        "fc": "MX",
        "mms_type": "float32",
        "quality_ref": "EMSLD0/MMXU1.TotW.q",
        "timestamp_ref": "EMSLD0/MMXU1.TotW.t"
      }
    ],
    "datasets": [
      {
        "dataset_ref": "EMSLD0/LLN0$measurements",
        "members": [{"object_ref": "EMSLD0/MMXU1.TotW", "fc": "MX"}]
      }
    ],
    "reports": [
      {"rcb_ref": "EMSLD0/LLN0.RP.urcb01", "dataset_ref": "EMSLD0/LLN0$measurements"}
    ]
  },
  "forwarding": [
    {"code": "power", "source_point_id": "已有遥测点的point_id", "stale_after_ms": 60000}
  ]
}

    通道 protocol=iec61850_mms、conn_mode=tcp_server，endpoint 为监听地址， 如 0.0.0.0:102；poll_interval_ms 是 RTDB 到出口映像的同步周期， timeout_ms 是每轮所有 RTDB 读取共用预算。网络读和报告只访问本地映像。 客户端按前述方式分配独立 URCB/BRCB，更新触发 dchg/qchg，完整性周期由 RCB 决定。

    每个服务端值点必须恰好映射一次，并配置 q/t；不允许两个出口别名竞争同一物理属性。 source_point_id 必须来自当前四遥配置中的 YC 或 YX，不能用业务 code 猜测身份， 也不能指向 YK/YT。出口直接使用 RTDB 中已完成缩放/取反的工程值，不重复做采集换算。 多个出口可引用同一源点。类型越界、非有限数、损坏记录、缺失点和停用来源均不会成为 good。

    有效记录的 timestamp 按 UTC 毫秒原样发布；它是来源数据时标，不是上送线程时间。 stale_after_ms 默认 60000，允许 1～86400000，按该时标计算陈旧；应结合设备时标是否 表示最后变位时间设置阈值。零时标或明显超前本机超过 5 秒的时标也按无效处理。 正常质量映射为 IEC good，非正常映射为 invalid，陈旧额外置 oldData。 无可用值时保留旧数值、将 q 置 invalid，并保留最后已发布时标；首次无值采用初始化 时刻且 q 无效。恢复后自动更新；未变化的映像不重复提交。

    服务端在监听前先建立无效映像并读取 RTDB。后台同步失败时停止监听，避免冻结 good 旧值。 停止时唤醒并等待上送线程、结束全部 MMS 会话、释放插件，再关闭 RTDB。站根 cfg_device.config_revision 变化时沿用进程现有轮询重建机制，停用映射或修改模型会关闭 旧会话并重建；不引入配置版本。非法映射在目录编译阶段拒绝，保留上次有效目录。

    可选 C 扩展 ems_plugin_update_image(instance, samples_json) 接收有界 JSON 数组， 每项包含 code、value、iec_quality、timestamp，在整批校验和原生值分配完成后， 用同一模型锁提交。value=null 仅更新 q/t 且不得声明 good。此扩展仅供本地装配使用， 不开放任何远端写入或控制。旧插件无需实现该扩展；用于自动上送的插件必须提供它。

    #9. 停止、重连与内存所有权

    停止顺序：拒绝新请求 → 结束轮询和报告任务 → 处理在途调用/命令 → 尽力禁用本实例 拥有的 RCB 并释放保留 → 注销 handler → 等待回调退出 → 销毁控制、DataSet、RCB 及模型规格对象 → close/destroy association → 清空缓存 → 销毁插件实例 → 释放库租约。 接收侧只记录断线，不在连接丢失回调内直接重连或销毁自身。

    原生对象所有权要求
    IedConnection实例独占；其依赖的控制对象先销毁，再 close/destroy
    IedConnection_readObject 返回的 MmsValue调用方拥有，处理后 MmsValue_delete，失败分支同样释放
    ClientDataSet按 API 创建/复用和销毁；其成员值只借用，不逐元素重复释放
    ClientReportControlBlock / ControlObjectClient库内 RAII 包装，分别调用对应 destroy；控制对象不能在终止回调内销毁
    目录链表 / 类型规格按具体 API 的所有权说明销毁列表元素及规格对象，不能仅释放链表头
    ClientReport 及其成员/引用字符串回调期间借用，不自行释放；回调返回前深复制需要保留的数据

    不能持有队列/注册表锁调用会等待回调的 uninstall/destroy，也不能把借用的 MmsValue 指针放入主程序队列。等待回调超时不意味着可以强制销毁；停止失败返回错误，利用现有 PluginManager 保留实例和库，避免代码仍执行时卸载。管理器须晚于通道工作线程析构。 重初始化失败清理候选实例，不破坏已经校验的原实例配置。

    #10. 第三方构建与插件工程接线

    #10.1 当前依赖可独立构建

    从仓库根目录执行，以下命令仅检查已有 C 栈，不生成 EMS 插件。 示例使用 Windows 已配置好的 MinGW 工具链；其他平台改用相应生成器。

    cmake -S backend/third_party/libiec61850 -B build/libiec61850-check `
  -G "MinGW Makefiles" -DCMAKE_C_COMPILER=gcc -DCMAKE_CXX_COMPILER=g++ `
  -DBUILD_EXAMPLES=OFF -DBUILD_TESTS=OFF `
  -DBUILD_PYTHON_BINDINGS=OFF -DCMAKE_POSITION_INDEPENDENT_CODE=ON `
  -DCONFIG_IEC61850_L2_GOOSE=OFF -DCONFIG_IEC61850_L2_SMV=OFF `
  -DCONFIG_IEC61850_R_GOOSE=OFF -DCONFIG_IEC61850_R_SMV=OFF
cmake --build build/libiec61850-check --target iec61850 --parallel 3

    该依赖提供 iec61850 静态目标、iec61850-shared 共享目标和 hal / hal-shared。 示例显式指定 GCC，避免同时安装 MSVC 时继承环境中的 CC/CXX；已有构建目录若使用 其他工具链，需换用空目录，不能混用编译器缓存。 EMS 插件优先静态链接 iec61850 及其 HAL，所有第三方类型留在插件内部；Linux 下 静态依赖也要开启 PIC。构建纯 MMS 不需要安装抓包 SDK；示例关闭未接入的二层及 路由组播能力，避免附带引入 WinPcap/mbedTLS。采样值相关编译选项保持 OFF。 TLS 是否编入仍须检查依赖 检测结果，不能仅凭运行时 JSON 开关宣称支持。

    #11. 与 ems_simulate 联调

    模拟器的使用步骤见其 IEC 61850 操作指南。 以下为模拟器与现场联调清单。已执行独立 C 栈服务端、报告故障帧与插件服务端回环测试； 客户端控制测试须待实现后执行，尚未完成 ems_simulate 界面或现场 IED 验收。

    1. 在模拟器新建 IEC 61850 服务端设备，导入 ICD/CID/SCD，选择具体 IED/访问点； 导入后显式启动 MMS。将服务端端口设为 10102，两端一致，避免默认 102 端口冲突。
    2. 从模型树记录实际 LD 名、对象引用、FC、MMS 类型和 q/t 路径，准备至少一个浮点 YC、 一个布尔 YX、一个双点状态；不要直接复制本文示例 LD 名。
    3. 创建包含标量和完整 FCD 的持久 DataSet，记录成员顺序；配置实际 URCB/BRCB 实例。 初次先用 poll 模式，确认读取值和无效点结果，再启用报告。
    4. 模拟器设置固定值后改值，检查 EMS 点值、q、UTC 时标、类型和上层系数换算； 同批加入一个不存在的引用，成功点必须仍返回，输入顺序不变。
    5. 启用报告，先验证 GI/初始同步，再测试 dchg、qchg、完整性报告、仅包含后部成员的 报告以及两个连接使用相同 RptId；EMS 不得串点或把未包含成员置零。
    6. 停止/重启模拟器 MMS，验证断线后样本失效、重新连接与订阅；修改 DataSet 成员后 确认旧投影被废弃。大模型下验证总预算和停止响应，不每轮全量发现。
    7. 单独开放测试控制点，依次验证 ctlModel 0～4、类型和检查拒绝、选择失败、终止负确认、 命令发出后断线。未知结果不自动重发；确认日志与状态回读证据。
    8. 交换角色验证只读服务端：EMS 发布固定模型，模拟器客户端读取与订阅；本地更新 可见，远端属性写入/控制被拒绝，多客户端报告各自独立。

    抓包核对 TCP/COTP/ACSE/MMS、对象域/变量、DataSet 成员、RCB 使能/GI、Report 的 inclusion/reason 和控制响应。模拟器与插件可能使用同一底层栈，互通通过仍须补充 独立 IED/第三方客户端测试，不能代替标准一致性或现场验收。
