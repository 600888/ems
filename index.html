    #架构与公共契约

    • 公共模块设计与实施规范：设备共享模型、目录与库依赖、配置/数据库/实时/消息接口与采样恢复边界、旧代码迁移及分阶段验收；后续公共模块编码从此文档开始。
    • EMS 系统架构设计：C++17 五类进程与 Vue 3 前端，实时后端生命周期与直接访问、ZeroMQ/gRPC 边界、储能设备模型、公共 ormpp API、MySQL/TDengine 与分阶段迁移。
    • 实时数据库进程详细设计：ems-rtdb 常驻管理、统一客户端、配置驱动的后端选择与扩展、共享内存/Redis 直接访问、恢复及受控切换。
    • 数据采集架构：C++17 采集进程、设备与通道绑定、独立采控/共用通道、事务边界插队、协议插件及可靠分发。
    • EMS 设备模型与点表绑定设计：PCS、BMS、电表、消防、空调、环控、保护与其他设备的固有点位、厂家点表、实例绑定、启用/禁用、导入页面与控制反馈。
    • Redis 键设计：全局唯一储能单元 code、递归设备 code 路径、station 公共资源、键目录、消费组、生命周期与迁移。
    • 公共实时数据访问接口设计（C++17）：抽象基类、共享内存/Redis/其他内存数据库派生类，统一读写与 CAS、错误语义、工厂注入、跨进程恢复和验收。
    • 设备、通道与协议：设备多通道绑定、采集/上送用途、客户端/服务端角色、协议 profile、资源、会话与点映射。

    #按进程阅读

    进程设计入口负责内容
    采集与上送 / C++17通信进程南向采样与执行、北向状态出口与外部意图受理
    实时数据库 / C++17实时数据库进程统一客户端、配置选择与扩展、后端生命周期、接入及受控维护
    存储 / C++17存储进程历史与审计归档、配置发布、outbox 与查询服务
    策略 / C++17策略进程聚合、告警、优化调度与控制仲裁
    Web / C++17 + DrogonWeb 后端与前端权限、配置页面、API 与实时展示编排

    策略进程详细设计给出防逆流、需量保护、计划曲线、手动模式与光伏协同的具体规则。

    #技术选型评估

    • Web 后端采用 Drogon：C++17 Web 技术栈、公共 MySQL Repository 与实施验收门槛。
    • ZeroMQ 消息订阅与命令下发设计：实时值与消息解耦、PUB/SUB 变更提示、REQ/REP 命令交接及恢复边界。
    • ZeroMQ 引入评估：引入前的历史评估和可靠性边界。

    #模块参考

    • 实时数据与配置：共享内存/Redis 最新值、数据管理、ZeroMQ 遥测/命令与存储服务配置发布。
    • libmodbuspp 指南：协议库使用参考。
