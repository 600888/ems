    #Web 进程设计

    日期：2026-10-24｜状态：首期 Web 与设备模块已实现；构建运行。设备设计 · API 契约。

    #1. 进程与业务模块

    模块所有权依赖边界
    identity登录、会话、主体与资源权限对外提供 Principal / Authorization
    device树、档案、绑定、四遥、模板、导入复用公共模型和数据库层
    health进程存活、依赖就绪、指标不探测现场设备
    channels（后续）通道连接与通信管理首期由 device 承接，移交时复用规则与事务
    monitoring / history / commands（后续）实时、历史、人工意图不通过配置接口执行设备命令

    配置保存即生效，以站根 config_revision 触发热加载；不建立配置草稿、发布、历史或回滚。

    #2. 目录与依赖

    按业务建目录，模块内再分层。以下为目标布局，仅创建本期实际使用的文件。

  CMakeLists.txt
  app/

  transport/

    response_writer.h/.cpp        # 统一响应与错误

      application/                # 对应服务与 configuration_writer

    规则落点
    Controller 只解析、调用、编码不包含 ORM、SQL、协议插件
    Service 管用例、授权、事务不依赖 Drogon 类型或全局容器
    模块之间只调 public不包含其他模块私有头文件，不形成循环
    SQL、行结构、ORM 只有一份include/common/database + src/common/db
    Web 内部头文件与实现相邻不复制到 include/web；接口写 Doxygen，遵守 .clang-format

    构建：Drogon + C++17，目标显式指定标准；新增 EMS_BUILD_WEB（初始 OFF），开启缺依赖则失败。纯应用测试不链接 Drogon；设备配置不链接采集引擎。Windows/MSVC 与 Linux/ARM 分别验收。

    #3. HTTP 统一入口

    约定内容
    路径固定 /api/模块/动作，不嵌入 ID，不使用 URL 查询串
    参数有参数一律 POST + JSON；GET 只用于无参数读取
    并发参数expected_config_revision、expected_preview_hash 均放 JSON
    上传例外multipart：file 为二进制文件，metadata 为 JSON 业务参数
    身份cookie、认证/CSRF 等安全头保留，不承载业务筛选与 ID
    编码UTF-8、snake_case；对象/数组直接传 JSON，不传转义 JSON 字符串
    JSON 库业务、配置、DTO 与序列化统一 nlohmann::json；JsonCpp 仅为 Drogon 内部依赖，不进入业务接口
    类型稳定 ID、revision、int64/uint64 为字符串；布尔为 boolean；缺失为 null
    响应成功 {data, meta}；失败 {error, meta}；时间为 UTC RFC 3339

    浏览器 Fetch 不允许 GET 请求体，因此需要参数的读取也使用 POST，见 Fetch 规范。POST 查询仍按只读权限授权，不增加 revision；响应使用 Cache-Control: no-store。API 未匹配返回 JSON 404，不能回退 SPA。

    #4. 请求与工作线程

    资源默认预算触限
    I/O 线程 / 普通线程 / 队列2 / 4 / 128满队列 503
    导入线程 / 队列 / MySQL 连接1 / 8 / 4有界等待；解析不占连接
    普通请求 / 导入 / 退出宽限期5 s / 30 s / 15 s超时保留写入确定性
    普通 JSON / 导入 metadata1 MiB / 64 KiB413，读取前限制
    导入文件 / multipart 整体 / XLSX 解压累计20 MiB / 21 MiB / 100 MiB超限拒绝，不截断
    导入行 / 批量改点50,000 / 200超限 422
    列表 / 树分页默认 20/100，最大 200/500非法值 400

    上传分别限制 multipart 总体、metadata、文件与解压量；有效上限取解析器和存储能力的交集。文件名不作磁盘路径，服务端随机工作区不对外静态开放。

    • 数据库、密码哈希、文件/解析、实时锁等待和长 RPC 在工作池执行；I/O 线程不做同步业务。
    • 排队计入 deadline；事务由同一线程创建和结束；超时与完成路径只能回复一次。
    • CallContext 现有字段为 deadline/trace_id，取消状态属于 Web 上下文；不强行销毁在途事务。

    #5. 启停、身份与异常

    项目约定
    连接沿用 EMS_DATABASE_CONFIG / EMS_MYSQL_*；Web 不复制数据库配置结构
    身份可替换账号提供者；首期可配账号哈希/权限，不内置默认密码
    会话HttpOnly + SameSite cookie；HTTPS 加 Secure；首期内存会话重启失效
    授权按数据库实际关系校验站、设备子树、绑定和任务，过滤列表与 total
    CSRFPOST 查询与写入统一检查；登录检查 Origin；后续 WebSocket 也检查来源
    审计同公共事务对接统一审计；不在 Web 建私有审计表
    健康GET /health/live、/health/ready；依赖缺失返回 503，采集离线不阻断配置
    部署同源；Drogon 静态服务或 Nginx 唯一入口；只信任配置中的代理

    Unknown 表示可能已提交，按原稳定 ID/任务查询；不自动更换 ID 重试。日志不记录凭据、cookie、完整文件或 DSN。

    #6. 实施顺序

    验收重点：真实分页、资源越权、站根锁并发、整批回滚、重复导入、过载与退出。MySQL 锁/约束单独验证；后续实时/历史依赖不作为首期配置就绪条件。
