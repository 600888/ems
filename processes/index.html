    #进程设计

    EMS 保持四类业务进程。采集与上送均由通信进程 ems-collector 承担，内部按用途隔离模块与队列；不因新增服务端协议就自动增加一种业务进程。后续可按负载拆分同类实例的通道分片。

    进程语言负责不负责
    采集与上送C++17南向采样/执行、北向状态出口/外部控制意图受理、协议和会话管理绕过策略直接执行上级控制、生成优化决策
    存储C++17历史审计、配置/outbox 发布、历史与可选实时查询服务现场协议、告警规则、调度仲裁
    策略C++17聚合、告警、优化调度、控制来源仲裁持有现场协议句柄、直接写设备
    Web 后端C++17 + Drogon身份权限、配置编辑/发布、业务 API、实时展示直连设备、将界面提交等同动作完成

    每个进程独立管理连接池、生命周期与健康状态；共享 C++ 公共库代码不代表共享连接对象。进程之间交换版本化数据，不传 C++ 对象内存布局。

    优先阅读 系统架构，再按负责的进程进入相应目录。设备、通道、协议模型统一引用 公共业务设计，不在不同进程重复定义。
