    #采集与上送进程

    进程：ems-collector｜语言：C++17｜状态：目标设计。

    该进程从现场设备取得状态，执行经策略仲裁的命令，并向调度中心或第三方系统提供标准状态。客户端/服务端是协议角色，采集/上送是业务用途。

    #模块与依赖

    模块职责主要依赖
    配置装载器加载完整版本，校验通道/profile/绑定/点映射，反馈应用状态配置仓储、公共 ormpp API
    通道管理器资源独占、通道实例、重连/监听、启停和版本切换协议工厂、资源协调
    采集执行模块轮询、报告/事件接收、解码、标准投影、执行和回读acquisition 绑定、厂家点路由
    上送模块标准点出口映像、总召/读取/报告、peer 权限和会话队列forwarding 映射、RealtimeService
    外部意图受理模块北向控制校验、持久保存意图/outbox、反馈受理与结果MySQL、公共 ormpp API、可靠回执
    数据分发器有界内存缓冲、最新值、ZeroMQ 原始遥测发布与丢样报告IRealtimeStore、ZeroMQ 遥测发布器
    执行命令入口消费已仲裁命令，校验去重/有效期/所有权，路由通道命令流、MySQL 执行状态/outbox

    采集与上送共享逻辑点模型和公共访问接口，不共享未经约束的驱动句柄。北向控制经过持久意图和策略仲裁后，才可能回到南向执行入口。

    配置、意图、inbox、执行状态及回执/outbox 统一调用公共 ormpp Repository，进程入口注入本进程数据库上下文；实体、连接管理和 SQL 不在采集模块重复实现。

    #线程与隔离

    执行单元隔离规则
    阻塞串口/轮询每独立资源一个工作线程；异步协议用事件循环
    listener / sessionlistener 管多会话；会话各有协议状态、发送窗口和有界队列
    配置/意图/采样/回调分别设预算；上送慢消费者不挤占采样和反馈
    队列满时背压或拒绝；最新值可显式合并，告警/命令/原始事件不统一覆盖

    #生命周期与状态

    分别报告进程存活、通道就绪、listener 状态、session 数量/状态、设备通信状态和测点新鲜度。服务端有连接不表示全部设备在线；北向断线不停止南向采样。

    #详细设计与验收

    • 设备、通道与协议：模型、角色矩阵、采集/上送映射、北向控制与例子。
    • 采集执行与协议插件：采集任务、调度、事务边界插队和数据分发。
    • 通讯协议动态库：PIMPL API、按需加载、C ABI、安全卸载与跨平台部署。
    • 公共实时访问接口：后端注入、版本并发与恢复。
    • libmodbuspp 开发参考：第三方 API 示例。

    验收覆盖一设备多通道、多设备共享资源、多上级会话、采控共用、慢消费者、旧配置迟到、重复/未知命令和退出恢复。各协议的客户端、服务端分别验收。
